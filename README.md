# Учебник DevOps & MLOps

Практический курс от терминала Linux до агентной LLM-систем в продакшне.
68 лекций, пять треков, ~89 часов материала.

## Как открыть

**Просто открой `index.html`** двойным кликом — сборка не нужна, всё
работает офлайн прямо из файловой системы.

Если хочешь нормальные ссылки и хочешь пересобирать при правках:

```
python build.py --serve
```

и открыть `http://localhost:8000/`.

## Структура

```
LLMops/
  index.html            <- открывать это
  lectures/             <- собранный сайт (генерируется)
    trainer/            <- тренажёр DevOps (генерируется)
  assets/               <- CSS и JS
    trainer/            <- движок симуляторов и оформление тренажёра
  content/              <- исходники лекций на Markdown  (правишь ты)
    trainer/source.html <- исходник тренажёра, из него генерируется страница
    index.md
    start/    02 лекции
    devops/   30 лекций
    net/      18 лекций
    mlops/    21 лекция
    ru/       03 лекции
    _STYLE_GUIDE.md      <- правила оформления новых лекций
  build.py              <- генератор сайта
  build-trainer.py      <- генератор страницы тренажёра
  minidown.py           <- markdown -> html
  template.html         <- каркас страницы
```

## Команды

| Команда | Что делает |
|---|---|
| `python build.py` | пересобрать сайт и тренажёр |
| `python build.py --serve` | пересобрать и поднять сервер на :8000 |
| `python build.py --stats` | статистика по курсу |
| `python build.py --check` | собрать и найти битые внутренние ссылки |
| `python build-trainer.py` | только тренажёр |

Зависимостей нет — нужен только Python 3.9+. На Windows можно запускать
`python`, на macOS/Linux иногда `python3`.

## Тренажёр DevOps

Практический стенд: настоящие команды в браузере, ничего не ломается.
**20 курсов, 321 задание.**

| Группа | Курсы |
|---|---|

| Сеть | Сетевое оборудование (18) — MikroTik и Cisco, VLAN, trunk, маршрутизация, `apply` после `check` |
| Данные и ИИ | RAG · PG (19), Промпты (20), Инференс (18) — `psql`/`pgvector`/`EXPLAIN`, promptfoo и регрессии качества, `nvidia-smi`/`ollama`/`vllm`, токены и цена |
| Агенты | Безопасность (18) — аудит действий через `jq`, маскирование ПДн через `sed`, prompt injection в корпусе, целостность через `sha256sum`, MCP и права на секреты |
| Продакшн | MLflow · Langfuse (17) — эксперименты и прогоны, реестр моделей, трейсы через API, метрики качества из Prometheus и алерты |
| Диплом | Инцидент · постмортем (18) — сквозной сценарий: `systemctl`/`journalctl`, метрики, откат через `git restore`, постмортем по шаблону |
| Месяц 1 | Python · ML (20) — `venv` и `pip`, чтение чужого кода, `asyncio`, тензоры на numpy, `pytest` и `mypy` |

Открывается с главной страницы и из лекций: в конце лекции появляется кнопка
«Потренироваться в тренажёре», которая сразу открывает подходящий курс.
Кнопка есть у всех 30 лекций DevOps, всех 18 сетевых, 23 лекции MLOps
и всех 3 лекций российского сегмента. Без кнопки остались только карта курса,
глоссарий и лекция о продажах — там практики нет by design.
В окне приветствия все курсы перечислены счётчиками и кликабельны.

Как это устроено:

- `content/trainer/source.html` — исходник исходного тренажёра (если заменишь
  на новую версию, положи сюда);
- `assets/trainer/engine.js` — **12 базовых курсов симуляторов** и терминальный
  движок (не менялся);
- `assets/trainer/courses.js` — заглушка подключения курсов;
- `assets/trainer/course-rag.js`, `course-prompt.js`, `course-inference.js`,
  `course-netdev.js`, `course-agents.js`, `course-mlops.js`,
`course-incident.js`, `course-python.js` — **8 новых курсов**, каждый в своём файле;
- `build-trainer.py` — переносит логику в `engine.js`, подключает все
  `course-*.js`, подменяет цвета на CSS-переменные темы сайта, собирает
  `lectures/trainer/index.html` и свои всплывающие окна;
- `assets/trainer/trainer.css` — оформление на токенах портала;
- `assets/trainer/_HOWTO.md` — **как добавить свой курс**: формат состояния,
  заданий, команд и обработчиков.

## Проверка

Две независимые проверки. Первая ловит логику курсов, вторая — то, что
Node не видит в принципе: реальный рендер, подключение скриптов, переключение
курса и правую панель.

```
node tools/check-courses.js              все курсы: 321 задание
node tools/check-courses.js rag 7,8      один курс, показать вывод
python build.py --check                  сборка сайта и проверка ссылок
```

`check-courses.js` проверяет не только то, что задание засчиталось, но и что
команда **реально отработала**: ловит «команда не найдена», упавшие
обработчики и мусор вида `undefined` в выводе. Без второй проверки курс может
показывать зелёные галочки, ни разу не выполнив ни одной команды.

Стенды в браузере:

| файл | что проверяет |
|---|---|
| `tools/browser-check.html` | все курсы разом: заголовок, приглашение, активная вкладка, текст задания, панель `env()`, копии баннера, ошибки JS |
| `tools/interaction-check.html` | живые действия: `#help`, `#finish`, `#chips`, `#start`, `#reset`, `#ctrlc`, `#light`, `#overflow` |

Оба грузят тренажёр в iframe и выполняют в нём настоящее действие, поэтому ловят
то, чего Node не видит: открытие окон, клавиши, сброс среды, переполнение вёрстки.

Браузерная проверка вручную (нужен Chrome, поднимается локальный сервер):

```
python -m http.server 8799
chrome --headless=new --disable-gpu --user-data-dir=<временная папка> ^
       --virtual-time-budget=6000 --window-size=1600,1000 ^
       --screenshot=shot.png "http://127.0.0.1:8799/lectures/trainer/index.html?course=incident"
```

Смотреть надо на: одну копию баннера в терминале, заголовок и приглашение
текущего курса, непустую правую панель, верное задание и вкладку в панели
курсов.

Внешних зависимостей (CDN) нет — тренажёр работает офлайн и наследует
светлую/тёмную тему учебника. Логика исходных 12 курсов не менялась.

## Как добавить лекцию

1. Создай `content/<трек>/<NN>-<slug>.md`.
2. Впиши frontmatter:

   ```yaml
   ---
   title: Название лекции
   track: devops
   module: A. Linux и сеть
   order: 7
   duration: 70 мин
   level: junior
   tags: [сеть, dns]
   summary: Одно предложение о том, что даёт лекция
   practice: Текст практического задания
   ---
   ```
3. Напиши текст по правилам из `content/_STYLE_GUIDE.md`.
4. `python build.py --check` — проверить ссылки.
5. Отметить как пройденную нельзя, пока не выполнена практика.

Ссылаться на другие лекции можно двумя способами, оба поддерживаются:
`[текст](16-prometheus.md)` (своя папка) и `[текст](mlops/08-llm-kak-ustroena.md)`
(от каталога `content/`).

## Публикация на GitHub Pages

Сайт статический и все ссылки внутри относительные, поэтому загружается
из подкаталога без единой правки: `https://<user>.github.io/<repo>/`.

В репозитории лежат и исходники (`content/*.md`, `*.py`), и собранный сайт
(`index.html`, `lectures/`, `assets/`) — GitHub Pages отдаёт последний.

Порядок:

1. Создать репозиторий на GitHub **пустым** (без README и `.gitignore`).
2. Отправить всё в ветку `main`:

```
git remote add origin https://github.com/<user>/<repo>.git
git push -u origin main
```

3. В репозитории: **Settings → Pages → Build and deployment → Source** —
   выбрать **Deploy from a branch**, ветка `main`, папка `/ (root)**, Save.
4. Через минуту сайт откроется по адресу, который покажет GitHub.

### Если нужно пересобрать и обновить

```
python build.py --check
git add -A
git commit -m "пересборка учебника"
git push
```

Pages пересоберётся автоматически. Ветку `main` лучше не форсировать —
иначе расходится история и ломается Pages.

### Почему собранный сайт в репозитории, а не через Actions

Без Actions страница зависит только от содержимого ветки: она не может
сломаться из-за неверного workflow. Сборка требует Python, а на сервере
GitHub Pages его нет. Если захочется собирать на каждый push — понадобится
`.github/workflows/pages.yml`; начиная с этого, файлы `lectures/` и `assets/`
из индекса можно убрать.
