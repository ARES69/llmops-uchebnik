# Как добавить курс в тренажёр

Спецификация для новых курсов симулятора. Прочитай целиком перед работой.

## Где что лежит

| Файл | Роль |
|---|---|
| `assets/trainer/engine.js` | ядро: 12 существующих курсов, логика заданий, терминал |
| `assets/trainer/courses.js` | общий файл-заглушка, новых курсов здесь не будет |
| `assets/trainer/course-<имя>.js` | **сюда пишешь новый курс — один курс в одном файле** |
| `assets/trainer/trainer.css` | оформление (уже в теме портала) |
| `lectures/trainer/index.html` | собирается из `content/trainer/source.html` скриптом `build-trainer.py` |

Файлы `course-*.js` подключаются **после** `engine.js` в алфавитном порядке
и дописывают курсы в объект `COURSES`. Один курс — один файл: так курсы
не мешают друг другу при правках.

## Формат курса

```js
var RAG = {
  docs: [], chunks: [], emb: {}, results: [], hits: [], evals: [],
  reset: function () {
    this.docs = []; this.chunks = [];
    this.emb = {}; this.results = []; this.hits = []; this.evals = [];
  },
  env: function () { /* html среды для правой панели */ },
  run: function (raw) { /* обработчик команд */ }
};

var RAG_MODS = [
  { id: 1, n: 'Данные',      c: 'var(--tr-accent)' },
  { id: 2, n: 'Индексация',  c: 'var(--tr-ok)' },
  { id: 3, n: 'Поиск',       c: 'var(--tr-cyan)' },
  { id: 4, n: 'Оценка',      c: 'var(--tr-accent2)' }
];

var RAG_LS = [
  { id: 1, m: 1,
    t: 'Загрузка документа',
    task: 'Скачайте документ reglament.md и положите в корпус: ingest reglament.md',
    re: /^ingest\s+reglament\.md$/,
    h: ['Векторная БД пуста, сначала нужно добавить документ.',
        'Команда начинается с ingest, затем имя файла.',
        'ingest reglament.md'],
    xp: 30 }
];

COURSES.rag = {
  i: '🧠', n: 'RAG', c: 'var(--tr-accent2)',
  pr: 'dev@rag-lab:~$', ti: 'dev@rag-lab — vector + llm',
  mods: RAG_MODS, ls: RAG_LS,
  run: function (raw) { var r = RAG.run(raw); renderEnv(); return r; },
  reset: function () { RAG.reset(); },
  env: function () { return RAG.env(); }
};
```

### Обязательные поля курса

| Поле | Тип | Обязательно | Пояснение |
|---|---|---|---|
| `i` | строка | да | иконка на вкладке, 1–2 символа |
| `n` | строка | да | ИМЯ КАПСОМ. Короткое: `RAG`, `ПРОМПТЫ`, `LLM`, `СЕТЬ` |
| `c` | строка | да | цвет из палитры, обязательно `var(--tr-...)` |
| `pr` | строка | да | приглашение терминала, например `dev@rag-lab:~$` |
| `ti` | строка | да | заголовок окна терминала |
| `mods` | массив | да | модули, поле `id` начинается с 1 и идёт подряд |
| `ls` | массив | да | задания, `id` начинается с 1 и идёт подряд |
| `run` | функция | да | обработчик команд |
| `reset` | функция | да | сброс состояния |
| `env` | функция | нет | если есть — праняя панель среды |
| `note` | строка | нет | честная оговорка, показывается на панели среды |

### Формат задания

```js
{ id: 1, m: 1,              // id сквозной по курсу, m — номер модуля
  t: 'Короткое название',  // видно в списке модулей и в справке
  task: 'Текст задания для ученика',
  re: /^вот\s+такая\s+команда$/,   // RegExp, по которому проверяется ответ
  h: ['намёк', 'подсказка', 'готовый ответ'],
  xp: 30 }
```

Требования к заданию:
- `id` уникален в пределах курса, **без пропусков**.
- `m` ссылается на существующий `id` модуля.
- `h[2]` — готовый ответ. `h` обязателен, все три уровня.
- `re` должен быть **строгим**: одно задание — одна команда. Не делай `/.*/`.
- Регулярку пиши так, чтобы она принимала и обычный порядок аргументов, и
  распространённые варианты (например короткие флаги), но **не принимала
  чужую команду**.
- `xp` — 20…50.

### Функция `run(raw)`

Возвращает:

| Возврат | Что происходит |
|---|---|
| строка | напечатать как обычный вывод (класс `t-tbl`) |
| `{t: '...', c: 't-ok'}` | напечатать с цветом |
| `null` | вывод уже произведён самой функцией через `out()`/`later()` |

Классы цвета вывода: `t-ok` (успех), `t-err` (ошибка), `t-tbl` (обычный),
`t-dim` (пояснение), `t-cmd` (ввод).

Доступные помощники из движка:

```js
out(text, 't-ok')           // напечатать строку сразу
later(['строка1','строка2'], 300)   // напечатать по очереди с задержкой (мс)
toast('текст', 'info')      // всплывающее уведомление: info | ok | err
envBlock('ЗАГОЛОВОК', rowsHtml)    // блок для правой панели
erow('метка', 'значение', 'цвет')  // строка «метка: значение»
```

Возвращать ошибку нужно **по-настоящему**, а не всегда успех:

```js
if (idx === -1) return { t: 'документ не найден: ' + name, c: 't-err' };
```

### Функция `env()`

Возвращает HTML для правой панели. Используй `envBlock` и `erow`:

```js
env: function () {
  return envBlock('ИНДЕКС',
    erow('документов', this.docs.length) +
    erow('чанков', this.chunks.length))
       + envBlock('ПОСЛЕДНИЙ ПОИСК',
    this.results.length ? this.results.slice(0, 5).map(function (r) {
      return erow(r.title, r.score.toFixed(3));
    }).join('') : erow('—', 'нет запросов'));
}
```

## ГЛАВНОЕ ПРАВИЛО: КОМАНДЫ ДОЛЖНЫ БЫТЬ НАСТОЯЩИМИ

> [!CAUTION]
> **Выдуманная утилита учит неправильно.** Студент выходит с ощущением
> «я научился искать по векторам», а в проде не может набрать ни одну из
> выдуманных команд. Это хуже, чем ничего: он будет уверен, что умеет.

**Плохо.** `ingest`, `search`, `rerank`, `eval`, `edit --system`, `device`,
`deploy` как отдельные команды — таких утилит нет ни в одном инструменте.
Запомнится несуществующий интерфейс.

**Хорошо.** `kubectl get pods`, `psql -c "SELECT ..."`, `curl -X POST ...`,
`ansible all -m ping`, `snmpwalk -v2c`, `promptfoo eval`, `vllm serve`,
`/interface/bridge/add` (RouterOS), `switchport access vlan` (Cisco),
`git commit`, `python ingest.py`.

Если единой утилиты под задачу нет — бери **то, что человек реально
набирает в работе**: `psql`, `curl`, `python`, `git`, `jq`. Именно так
устроена настоящая работа с RAG и с промптами.

Если всё же приходится моделировать процесс, обязательно:

1. добавь в курс поле `note` — честная оговорка, что это модель процесса,
   а не реальная утилита;
2. в первом задании модуля 1 текст теории (`th`) начни с этой оговорки;
3. имя курса должно это показывать: `RAG: процесс`, а не `RAG`.

**Проверка перед сдачей:** есть ли в курсе хоть одна команда, которую можно
набрать в настоящем терминале? Если нет — переделай.

## Правила содержания

1. **Команды — настоящие.** Пиши те команды, которые DevOps вводит в реальности:
   `kubectl`, `psql`, `docker`, `curl`, `snmpwalk`, `/ip/firewall/print`.
   Выдуманные команды учат неправильно.
2. **Состояние живое и меняется.** Задание выполнило — состояние изменилось,
   следующее задание видит результат. Порядок заданий важен, и он проходим.
3. **Ошибки реальные.** Если команда неверная — пиши правдоподобный вывод ошибки
   в стиле настоящего инструмента. Это половина обучающей ценности.
4. **Нельзя сломать.** Любая команда не должна ронять скрипт. На незнакомую
   команду возвращай подсказку, а не молчи.
5. **4–5 модулей, 14–18 заданий** на курс.
6. Язык интерфейса и пояснений — **русский**. Команды и вывод инструментов —
   как в жизни (английские ключи, русский текст заданий).
7. Никаких `eval`, `innerHTML` с пользовательским вводом, никаких зависимостей.

## Как проверить

Из корня проекта:

```
node --check assets/trainer/course-<имя>.js     синтаксис нового курса
node tools/check-courses.js <ключ>              прогон всех заданий курса
node tools/check-courses.js <ключ> 3,7          прогон + показать вывод заданий 3 и 7
python build.py --check                         пересобрать и проверить ссылки
```

`check-courses.js` проверяет не только то, что задание засчиталось, но и что
команда **реально отработала**. Без второй проверки можно получить зелёные
галочки, ни разу не выполнив ни одной команды: регулярка задания совпадёт,
а обработчик о команде не знает и молча отдаст «команда не найдена».

Затем в браузере: `lectures/trainer/index.html?course=<ключ>`.
Полная проверка всех курсов разом: открой `tools/browser-check.html`
при запущенном `python -m http.server`.

Пройди курс целиком — каждое задание должно засчитываться.

Дополнительно проверь вручную:

- `COURSES.<ключ>` существует после загрузки страницы;
- вкладка курса появилась в `tabBar`;
- `help` в терминале показывает твои задания;
- после сброса (`⟲`) состояние чистое.
