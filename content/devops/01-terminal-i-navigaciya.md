Терминал — не «консоль для тех, у кого нет кнопки». Это интерфейс, через который
автоматизируется всё, что ты делаешь руками. Любой GUI-клик имеет эквивалент в
командной строке, и обратное верно не всегда: часть того, что ты делаешь вручную
(найти конфиг, вытащить из лога строки по маске, посмотреть, что слушает порт) в
GUI либо недоступна, либо требует пяти кликов. Через два-три месяца работы ты
поймёшь, что мысль «дай мне терминал» приходит раньше, чем мысль «открой панель».

Все примеры лекции рассчитаны на твою Ubuntu-ВМ в Proxmox. Подключись к ней по SSH
и держи терминал открытым — всё, что ниже, копипастится.

## Почему не GUI

GUI хорош там, где нужно **посмотреть**: метрики, дашборд, список ресурсов в Proxmox.
Плох там, где нужно **сделать**: снять дамп, прогнать по ста файлам замену, найти
одну строку среди десяти тысяч и понять, в каком файле она живёт.

Три практических отличия терминала от GUI:

- **Композиция.** Результат одной команды можно передать другой. В GUI ты либо
  копируешь руками, либо у тебя таблица без поиска и фильтров.
- **Повторяемость.** Скрипт `find ... -exec ...` работает на 10 файлах и на 100 000.
  Клик мышью по 100 000 — нет.
- **Удалённость.** SSH-сессия к ВМ, контейнеру, `docker exec`, `kubectl exec` —
  единственный способ работать с системой, у которой нет экрана. Linux-сервер в
  проде *всегда* без экрана.

> [!IMPORTANT]
> Не начинай с мнемоник. Мнемоники приходят через месяц ежедневной работы, когда
> пальцы начут находить `Ctrl+R` сами. Сейчас важнее понимать пайпы и кавычки.

## Перемещение по каталогам

Каталог — это текущее место. Всё, что ты запускаешь, ищется относительно него, и
почти все сообщения об ошибке дают относительный путь. Ошибся один раз — дальше
чинишь не ту папку.

| Что нужно | Команда | Что делает |
| --- | --- | :--- |
| Где я | `pwd` | печатает абсолютный путь |
| Домой | `cd ~` или просто `cd` | `~` — это `/home/<твой_юзер>` |
| На уровень выше | `cd ..` | |
| Назад | `cd -` | в предыдущий каталог — то, что ты забыл |
| В корень | `cd /` | |
| Сменить каталог и сразу уйти | `(cd /etc && ls -l)` | скобки создают подоболочку |

`cd -` — самая недооценённая команда. Реальный сценарий: ты в `/var/log/nginx`,
понял, что нужен `/etc/nginx`, открыл его, забыл зачем пришёл. `cd -` возвращает.

> [!TIP]
> В `~/.bashrc` добавь `cd` как алиас для `cd "$HOME"` и, если пользуешься zsh,
> включи `cd -<TAB>` для автодополнения по каталогам. Мелочь, которая
> заменяет десятки `cd /home/user/...` в день.

### Что лежит в каталоге

`ls` без аргументов показывает «красиво», но для работы бесполезно. Рабочий
вариант — длинный формат со скрытыми файлами, отсортированный по времени
изменения: именно так ты находишь свежее изменённый конфиг.

```bash
ls -laht /etc/nginx/          # все файлы, включая скрытые, свежие сверху
ls -lah /etc/nginx/           # то же, но с размером в человекочитаемом виде
ls -lahd /etc/nginx/          # сам каталог, а не его содержимое
ls -l /etc/nginx/sites-enabled/
```

| Флаг | Смысл |
| --- | --- |
| `-a` | показать `.` и `..` и скрытые файлы |
| `-l` | длинный формат: права, владелец, размер, дата |
| `-h` | размер как `4.0K`, а не `4096` |
| `-t` | сортировать по времени изменения, свежие сверху |
| `-S` | сортировать по размеру, большие сверху |
| `-d` | показать сам аргумент, а не содержимое каталога |

Скрытые файлы начинаются с точки — это `.bashrc`, `.ssh/config`, `.profile`,
`.docker/config.json`. Именно в них лежат настройки, поэтому «ничего не
нашлось в `~/.ssh`» почти всегда означает, что ты забыл `-a`.

> [!CAUTION]
> `ls` без `-a` — самая частая причина получаса на поиски несуществующего
> файла. Если что-то «не находится», первым делом повтори с `-a`.

## Как читать вывод: cat, head, less, tail

Четыре команды, которые выглядят похоже, но решают разные задачи.

| Задача | Команда | Вывод |
| --- | --- | --- |
| Быстро глянуть короткий файл | `cat file` | весь файл разом |
| Начало файла | `head -n 50 file` | первые 50 строк |
| Конец файла | `tail -n 200 file` | последние 200 строк |
| Читать постранично, искать | `less file` | постраничный просмотр |
| Следить за логом в реальном времени | `tail -f /var/log/syslog` | живой хвост |

`tail -f` — рабочий инструмент дежурного. Открыл в одном окне лог nginx,
во втором — перезагрузил конфиг, увидел, что появилась ошибка. `tail -F`
делает то же самое, но переоткрывает файл, если он был переименован или
пересоздан — редакторы и logrotate это любят.

```bash
tail -f /var/log/syslog                      # живой хвост
tail -n 500 /var/log/syslog | less           # последние 500 строк с поиском
tail -f /var/log/nginx/error.log | grep -i 'upstream\|connect' \
  | grep --line-buffered ' 500 '             # только ошибки, живая фильтрация
grep --line-buffered -i 'timeout' /var/log/nginx/error.log | tail -f /dev/stdin
```

Последний приём (`--line-buffered` + `tail -f /dev/stdin`) нужен, чтобы
`grep` не заливал буфер по 4 КБ и результат появлялся построчно.

### less — страница, в которой ты будешь жить

`less` открывает длинный вывод постранично. Клавиши, которые реально нужны:

| Клавиша | Действие |
| --- | --- |
| `/слово` | поиск вперёд, `Enter` — следующее совпадение |
| `?слово` | поиск назад |
| `n` / `N` | следующее / предыдущее совпадение |
| `g` / `G` | в начало / в конец файла |
| `q` | выход |
| `Ctrl+F` / `Ctrl+B` | страница вперёд / назад |
| `-S` | не переносить длинные строки (удобно для логов и YAML) |
| `v` | открыть текущий файл в `$EDITOR` |

Комбинация `-S` — то, что ты будешь набирать постоянно: без неё длинная строка
JSON в логе переносится и становится нечитаемой.

```bash
journalctl -u nginx --since "1 hour ago" | less -S
man sshd_config | less      # ищи: /Timeout
```

## Где искать: man, --help, find, grep

`--help` быстрее, `man` полнее. Стратегия: сначала `--help`, если не хватило —
`man`. `man` открывается в `less`, поэтому работает `/` — тот же поиск.

```bash
grep --help
ls --help | less
man find          # поиск: /-mtime
man 5 crontab     # раздел 5 — формат файлов, не команда
```

| Что ищешь | Команда |
| --- | --- |
| Где лежит программа | `which docker` |
| Что это вообще (скрипт, алиас, встроенная команда) | `type -a grep` |
| Все файлы по имени, глубоко по дереву | `find /etc -name '*.conf'` |
| По содержимому, рекурсивно | `grep -rn 'worker_processes' /etc/nginx` |
| По содержимому, расширенный regex | `grep -rE 'listen (80|443)' /etc/nginx` |
| По содержимому, без учёта регистра | `grep -rni 'timeout' /etc` |
| По содержимому, из пайпа | `ps aux \| grep nginx` |
| Быстрый поиск по всей системе | `locate nginx.conf` (нужен `mlocate`) |
| Кто в каталоге | `whoami`, `id`, `groups` |

`which` показывает только исполняемые файлы. `type -a` показывает всё: алиас,
функцию bash, встроенную команду. Если ты создал алиас `ls='ls --color=auto'`
и удивляешься, почему скрипт ведёт себя иначе, — это `type -a`.

> [!NOTE]
> `locate` работает по индексу, а не по реальной ФС: он находит удалённый день
> назад файл и не находит созданный минуту назад. Для точных ответов
> используй `find`. `locate` хорош, когда ты знаешь, что файл где-то есть, и
> надо просто вспомнить путь.

### Практический приём: три вопроса, которые ты задаёшь каждый день

**«Кто занял порт?»** — самый частый вопрос при работе с Docker и systemd:

```bash
sudo ss -tulpn | grep ':8080'
sudo lsof -i :8080
sudo fuser -v 8080/tcp          # кто держит, убить можно через -k
```

**«Что слушает?»** — обзор всех слушающих сокетов:

```bash
sudo ss -tulpn
sudo netstat -tulpn             # если net-tools ещё стоит
```

**«Где лежит конфиг?»** — от симптома к файлу:

```bash
systemctl cat nginx                       # покажет все конфиги юнита
nginx -T                                 # весь собранный конфиг с путями
docker inspect nginx --format '{{.Mounts}}'
grep -rn 'server_name' /etc/nginx /opt/app 2>/dev/null
find / -name 'nginx.conf' -not -path '*/proc/*' 2>/dev/null
```

`nginx -T` — команда, которая экономит час. Она печатает **все** подключённые
конфиги с комментариями-путями, после чего ты видишь рабочую конфигурацию, а не
предполагаемую.

## Пайпы и перенаправления

Суть Unix в одном предложении: **программа читает stdin и пишет stdout, ошибки
идут в stderr**. Всё остальное — перенаправления.

| Синтаксис | Что делает |
| --- | --- |
| `cmd > file` | stdout в файл, файл перезаписывается |
| `cmd >> file` | stdout в файл, дописывается в конец |
| `cmd 2> file` | stderr в файл |
| `cmd > file 2>&1` | и stdout, и stderr в файл |
| `cmd &> file` | то же в bash, короче |
| `cmd < file` | stdin из файла |
| `cmd \| next` | stdout текущей в следующую команду |
| `cmd \|& next` | stdout **и** stderr в следующую |

Порядок важен. `> out 2>&1` перенаправляет stdout в файл, а затем *дублирует*
уже перенаправленный stdout в stderr — оба потока идут в файл. `2>&1 > out`
сначала дублирует stderr в текущий stdout (терминал), потом уводит stdout в
файл — stderr остаётся на экране. Это самая частая причина «почему ошибка не
попала в лог».

```bash
# прогнать конфигурацию и сохранить всё, включая ошибки, в лог
nginx -t > /tmp/nginx-test.log 2>&1

# то же самое на дежурстве: видно ошибки в консоли, полный лог в файле
docker logs web 2>&1 | tee -a /tmp/web-debug.log | grep -i error
```

### xargs: когда find ничего не умеет

`find` умеет только искать. Чтобы что-то сделать с результатом, нужен `-exec`
(медленно: новый процесс на файл) или `-print0 | xargs -0` (быстро, переживает
пробелы в именах).

```bash
# удалить найденные бэкапы старше 30 дней
find /var/backups -name '*.sql.gz' -mtime +30 -print0 \
  | xargs -0 -r ls -lh

# пересобрать права на конфигах
find /opt/myapp/config -name '*.yaml' -exec chmod 640 {} \;

# сколько места занимает каждый каталог в /var
sudo du -sh /var/*/ 2>/dev/null | sort -h
```

`-r` у `xargs` означает «не запускай команду, если вход пуст». Без него
`xargs rm -rf` на пустом результате напечатает `rm: missing operand` — безвредно,
но в скриптах с `set -e` это лишний повод для падения. Подробнее про
скрипты — в [лекции про Bash](devops/05-bash-skripty.md).

## Кавычки — главная ловушка bash

Однокавычки отключают **всё**. Двойные кавычки отключают **почти** всё, кроме
`$`, `` ` ``, `\` и `"`.

```bash
# ОДИНАРНЫЕ — литерал, ничего не подставится
echo '$USER не выполнится'
# ДВОЙНЫЕ — подставится переменная
echo "$USER выполнится"

# Кавычки ломают парсинг
rm -rf "/var/lib/my app"       # каталог с пробелом — без кавычек это 2 аргумента
grep 'weight decay' conf.yaml  # иначе grep увидит три аргумента
echo "переменная: $HOSTNAME"
echo 'переменная: $HOSTNAME'
```

> [!CAUTION]
> По умолчанию всегда используй **двойные** кавычки: `"$VAR"`. Голое `$VAR`
> разваливается на пробелах и на пустом значении — классический баг
> `[ $x = 1 ]`, который падает с «unary operator expected», когда `x` пуст.

Подстановка команд внутри кавычек:

```bash
now=$(date +%F)                # результат команды в переменную
echo "сегодня $now, хост $(hostname)"
size=$(stat -c %s file.bin)    # без кавычек -c% 1 разобьётся
```

### Экранирование пробелов и спесимволов

```bash
touch report\ 2024.txt        # пробел через обратный слэш
touch "report 2024.txt"       # то же, но читаемее — используй кавычки
touch 'it'"'"'s'              # одинарная кавычка внутри одинарных — три куска
mkdir -p /opt/app/{bin,etc}   # {} — раскрытие в три каталога
```

> [!TIP]
> Всегда заключай в кавычки **переменные и подстановки команд**: `"$var"`,
> `"$(cmd)"`. Никогда — не весь текст. Это правило убирает класс багов, которые
> проявляются раз в месяц на пустых значениях.

## История и горячие клавиши

| Клавиши | Действие |
| --- | --- |
| `↑` / `↓` | предыдущая / следующая команда |
| `Ctrl+R` | обратный поиск по истории — **самая полезная клавиша** |
| `Ctrl+A` / `Ctrl+E` | в начало / конец строки |
| `Ctrl+U` / `Ctrl+K` | удалить до начала / до конца строки |
| `Ctrl+W` | удалить последнее слово |
| `Ctrl+L` | очистить экран (не скроллит — просто чистит) |
| `Ctrl+C` | прервать текущую команду (SIGINT) |
| `Ctrl+D` | EOF — завершить ввод, выйти из шелла |
| `Ctrl+Z` | приостановить (suspend), `fg` — вернуть |
| `Alt+.` | вставить последний аргумент предыдущей команды |
| `!!` | повторить последнюю команду целиком |

`Ctrl+R` работает так: жмёшь, набираешь `nginx -T`, видишь все команды, где это
встречается, жмёшь Enter на нужной. Запоминать историю не нужно.

> [!WARNING]
> В `.bash_history` лежат команды **как есть**. Если ты вводил
> `mysql -u root -pSECRET`, пароль теперь в истории, а `history -c` не поможет —
> файл уже записан на диск. Проверяй историю регулярно:
> `history | grep -i 'password\|secret\|token'`. Правильный способ — читать пароль
> из переменной окружения или из защищённого файла.

Файл истории по умолчанию `~/.bash_history`, но в текущей сессии живёт
переменная `HISTFILE`. Полезные настройки, которые стоит добавить в `~/.bashrc`:

```bash
export HISTSIZE=10000            # сколько команд помнить в памяти
export HISTFILESIZE=20000        # сколько хранить на диске
export HISTCONTROL=ignoreboth    # не писать команды, начинающиеся с пробела
export HISTTIMEFORMAT='%F %T '   # дата и время рядом с каждой командой
export HISTIGNORE='ls:ll:pwd:clear:exit'
```

`HISTCONTROL=ignoreboth` — первое, что стоит включить. Команда, набранная с
-leading пробелом, не попадает в историю: так ты вводишь пароль в интерактивной
сессии, не сохраняя его.

`!!` и `!` — история по шаблону. Полезно, но опасно:

```bash
sudo systemctl restart nginx    # забыл sudo
!!                             # повтор с sudo — работает
!nginx                         # последняя команда, содержащая "nginx"
!$                             # повтор с последним аргументом
```

> [!CAUTION]
> `!!` в скрипте или в неинтерактивном окружении не раскрывается. В
> автоматизации используй явные переменные и повторяй команды явно, а не
> через историю. Подробности — в [скриптах на Bash](devops/05-bash-skripty.md).

## Практика

На своей Ubuntu-ВМ выполни и сохрани в `~/lab1/`:

```bash
mkdir -p ~/lab1
{
  echo "=== кто слушает ssh ==="
  sudo ss -tulpn | grep ':22'
  echo
  echo "=== порт в nginx.conf ==="
  grep -rn 'listen' /etc/nginx/ 2>/dev/null
  echo
  echo "=== файлы конфигурации nginx ==="
  find /etc/nginx -type f -name '*.conf'
  echo
  echo "=== размеры логов ==="
  du -sh /var/log/* 2>/dev/null | sort -h | tail -5
} | tee ~/lab1/report.txt
```

Дополнительно: открой `less ~/lab1/report.txt`, поищи через `/nginx`, выйди по
`q`. Затем перезапусти `nginx` в одном окне и следи за логом во втором через
`tail -f`.

## Где это ломается

- **Конвейер без `pipefail`.** `false | echo ok` печатает `ok` и возвращает код
  0. В CI-скрипте это означает «тест зелёный» при провалившемся тесте. В
  конвейере вручную ты хотя бы видишь пустой вывод — но в скрипте это молчаливая
  поломка. Лечится `set -o pipefail`.
- **`grep` в пайпе находит самого себя.** `ps aux | grep nginx` показывает и
  самим `grep`. Лечится `grep '[n]ginx'` — квадратные скобки ломают совпадение
  с собственной командной строкой.
- **Битые ссылки и симлинки.** `ls` показывает `@` в начале строки и указывает на
  `broken`. Это симлинк в никуда — частая история после переезда каталогов.
  Подробно — в [лекции про файловую систему](devops/02-fajlovaya-sistema-i-prava.md).
- **Кавычки потерялись при копипасте из чата.** Очень частая ошибка:
  `curl -H "Authorization: Bearer $TOKEN"` скопирован без кавычек —
  `$TOKEN` разваливается на пробелы, и заголовок уезжает битым. Всегда кавычки
  вокруг значений с `$`.
- **`sudo` теряет окружение.** `export TOKEN=...` в обычной сессии не видно под
  `sudo`. Если переменная «пропала после sudo» — это оно. Решение —
  [переменные окружения в systemd-юнитах](devops/03-processy-i-systemd.md).
- **Битые однострочники из интернета.** `curl ... | bash` без проверки — это
  запуск чужого кода с правами root. Для установки пакетов есть `apt`, для
  настройки — Ansible. Подробнее в [следующей лекции](devops/02-fajlovaya-sistema-i-prava.md).
