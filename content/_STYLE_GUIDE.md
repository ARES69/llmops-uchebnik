# Стиль-гайд учебника (обязателен для всех лекций)

Этот файл — техническая инструкция по формату. **Прочитай его перед написанием лекции.**

## 1. Формат файла

Лекция — обычный Markdown-файл в `content/<track>/<NN>-<slug>.md`.
Имя файла — латиницей, kebab-case, с порядковым номером. Заголовок в frontmatter — на русском.

## 2. Frontmatter — строго этот вид

```
---
title: Короткое название лекции
track: devops
module: A. Linux и сеть
order: 4
duration: 70 мин
level: junior
tags: [сеть, ip, dns, диагностика]
summary: Одно предложение — что студент узнает из лекции
practice: Текст практического задания в 1-3 предложения
---
```

Допустимые `level`: `junior`, `middle`, `senior`.
`duration` — с числом в минутах, например `45 мин` или `1.5 ч`.
`tags` — 4-6 тегов в квадратных скобках, латиницей или кириллицей, без кавычек.
Строки frontmatter пишутся **без отступов**.

Значения `track`, `module`, `order` и `title` тебе выданы в задании — **не меняй их**.

## 3. Структура тела лекции

Обязательная схема. Заголовки — только `##` и `###` (никакого `#` в теле!).

```
Короткий абзац-мостик: о чём лекция и почему это важно именно сейчас.

## <Смысловой раздел 1>

## <Смысловой раздел 2>

...

## Где это ломается

3-6 пунктов с реальными граблями из практики.

## Чек-лист понимания

- [ ] 4-6 пунктов: студент может проверить себя
```

Правила:
- **Ни одного `#`** в теле. `##` — крупные разделы, `###` — подразделы.
- Каждый `##` — законченная мысль, не более ~400 слов без кода и таблиц.
- Раздел «Где это ломается» обязателен **в каждой лекции** — это отличие хорошего учебника от пересказа документации.
- В конце — 4–8 чекбоксов `- [ ]` в разделе «Чек-лист понимания».

## 4. Поддерживаемая разметка

Разрешено:

```markdown
# ## ### #### — заголовки (в теле только ## и ###)

**жирный**, *курсив*, `инлайн-код`, ~~зачёркнутый~~
[текст ссылки](https://example.com)
[внутренняя лекция](devops/16-prometheus.md)   ← путь ОТ content/, .md

> обычная цитата

> [!NOTE]
> заметка — дополнение

> [!TIP]
> подсказка — как сделать правильно

> [!WARNING]
> предупреждение — необратимое действие, потеря данных

> [!IMPORTANT]
> важно — ключевая мысль лекции

> [!CAUTION]
> осторожно — ловушка, в которую попадают все

- пункт
- пункт
  - вложенный пункт
1. нумерованный
2. нумерованный

- [ ] чекбокс задачи

| Колонка | Колонка | Колонка |
|---------|:-------:|--------:|
| значение |  значение | значение |

```bash
# блок кода: язык обязателен
docker ps -a
```

---

тер­­мин — определение
```

**Запрещено** (рендерер не поддержит):
- Сырой HTML (`<div>`, `<br>`, `<span>`) — вообще.
- Вложенные тройные-backtick блоки кода внутри блоков кода.
- Шапки `|:` — не работает, пишите `| :--- |`... — тоже не работает, пишите `| --- | :---: | ---: |`.
- Сноски `[^1]`, сноски markdown.
- Математические формулы `$...$` — вместо них пиши словами или используй блок кода.
- Эмодзи в заголовках `##`.

Используемый синтаксис выравнивания в таблицах:

```markdown
| Лево | Центр | Право |
| --- | :---: | ---: |
```

## 5. Стиль текста

- Язык — русский, обращение на «ты» (курс для практикующего инженера).
- **Сначала объяснение, потом команда.** Никогда не начинай раздел с флага.
- Никаких «просто», «очевидно», «elementary». Если что-то очевидно — не пиши об этом.
- Не пересказывай документацию. Пиши то, чего в документации нет: почему так, когда не так, что сломется.
- Все примеры — воспроизводимые, копипастятся в терминал.
- Если пример требует твоей инфраструктуры, скажи это явно.
- **Минимум воды, максимум конкретики.** Лучше 5 плотных абзацев, чем 15 пустых.

## 6. Обязательные элементы каждой лекции

1. **Абзац-мостик** в начале: зачем это читать, где пригодится.
2. **Минимум 3 блока кода** с реальными командами (кроме чисто теоретических лекций).
3. **Минимум 2 таблицы** для сравнений/матриц решений.
4. Раздел **«Где это ломается»** с реальными граблями.
5. Раздел **«Чек-лист понимания»** с 4–8 чекбоксами.
6. Ссылки на соседние лекции там, где это помогает навигации:
   `[следующая лекция](devops/17-grafana-loki-alerty.md)`.

## 7. Ориентир по объёму

- `duration: 45 мин` → 900–1300 слов
- `duration: 60 мин` → 1300–1800 слов
- `duration: 75 мин` → 1800–2400 слов

Объём = **плотность**, а не длина. Лучше меньше текста и больше работающих примеров.

## 8. Контекст студента

У него такой бэкграунд — держи это в виду:

- Работает DevOps-инженером, руководит IT-отделом.
- У него в реальном контуре: **Proxmox** с виртуалками, среди них **Windows AD (Domain Controller)** и **Linux на Ubuntu**.
- Цель — перейти в LLMOps: стать архитектором AI-систем и владельцем продукта, а не ML-разработчиком.
- Ему не нужно писать loss-функции. Ему нужно **понимать, ставить задачи команде, оценивать риски и бюджеты**.

Поэтому:
- Приоритет — инфраструктура, эксплуатация, наблюдаемость, стоимость.
- Математику объясняй интуитивно, через аналогии и через влияние на бизнес.
- Каждая лекция должна давать либо руку-код, либо руку-решение для реальной системы.
