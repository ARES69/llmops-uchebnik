## Инфраструктура и эксплуатация

**Контейнер** — изолированный процесс с собственным файловым пространством,
сетевым интерфейсом и ограничениями по ресурсам. Легче виртуальной машины,
потому что делит ядро ОС с хостом.

**Образ (image)** — неизменяемая файловая сборка: слои файловой системы плюс
метаданные запуска. Из одного образа запускается сколько угодно контейнеров.

**Оркестратор** — система, которая сама решает, где и когда запускать
контейнеры, и перезапускает их при падении. Пример: Kubernetes.

**Инфраструктура как код (IaC)** — описание инфраструктуры в файлах версионируемой
системы вместо ручных действий. Пример: Terraform.

**Изменяющийся дрейф** — когда реальное состояние инфраструктуры разошлось с
описанием в коде, потому что кто-то изменил его руками.

**Согласованность данных** — состояние, в котором все копии данных (например,
реплики базы или файлы бэкапа) находятся в одном непротиворечивом состоянии.
Снятие копии с «живой» системы без подготовки часто даёт непригодный бэкап.

**RPO** (Recovery Point Objective) — сколько данных вы готовы потерять,
измеряется во времени. «RPO 15 минут» означает максимум 15 минут работы,
потерянных при аварии.

**RTO** (Recovery Time Objective) — за сколько времени сервис должен
вернуться в работу после аварии.

**Золотой набор (golden set)** — фиксированный набор размеченных примеров
с эталонными ответами, на котором меряется качество системы. Основа для
автоматических проверок качества в CI.

## Наблюдаемость

**Метрика** — числовая величина, измеренная в конкретный момент времени:
«запросов в секунду», «занято памяти», «доля ошибок». Дёшево хранить, удобно
смотреть на графике.

**Лог** — текстовая запись события с временем, уровнем и контекстом. Подробнее
метрики, но дороже хранить. Отвечает на вопрос «что именно произошло».

**Трейс** — запись пути одного запроса через все сервисы, с таймингами и связями
между шагами. Самый дорогой вид данных. Отвечает на вопрос «где именно
задержалось».

**Наблюдаемость (observability)** — способность системы описать своё
внутреннее состояние снаружи, по внешним сигналам, без доступа к коду.

**USE** — метод оценки инфраструктуры: **U**tilization (загрузка),
**S**aturation (насыщение, очередь), **E**rrors (ошибки).

**RED** — метод оценки сервисов: **R**ate (частота запросов),
**E**rrors (ошибки), **D**uration (задержка).

**SLI** — измеримый показатель качества сервиса (например, «99% запросов
успешны»).

**SLO** — целевое значение SLI, договорённость внутри команды.

**Error budget** — «бюджет» допустимых отказов: разница между 100% и SLO.
Если потрачен — новые фичи ждут, инженеры чинят надёжность.

**Burn rate** — скорость расхода error budget. Если SLO 99,9% и бюджет
расходуется в 10 раз быстрее нормы, значит через несколько часов бюджет
кончится досрочно.

**Кардинальность** — количество уникальных комбинаций значений лейблов.
Рост кардинальности взрывает память системы хранения метрик.

**Exporter** — маленькая программа, которая отдаёт метрики сервиса в формате,
который понимает система мониторинга.

**Scraping** — сбор метрик системой мониторинга по расписанию (pull-модель).

## Машинное обучение и LLM

**Модель** — обученная функция, отображающая вход в выход. Параметры (веса)
найдены в процессе обучения.

**Обучение (training)** — подбор весов модели на размеченных данных.

**Переобучение (overfitting)** — модель выучила обучающую выборку, но не
закономерность. На новых данных работает плохо.

**Признаки (features)** — входные данные, по которым модель делает предсказание.

**Разметка (labels)** — правильные ответы, на которых учат модель.

**Эмбеддинг (embedding)** — вектор чисел, кодирующий смысл текста. Похожие
по смыслу тексты дают похожие векторы.

**Векторная база данных** — хранилище эмбеддингов с быстрым поиском
«ближайших соседей» по смыслу, а не по точному совпадению.

**Токен** — минимальная единица текста для модели (обычно часть слова).
Модель оперирует токенами, и от их количества зависит цена запроса.

**Контекстное окно** — максимальное количество токенов, которое модель
удерживает за один запрос. Всё, что не влезло, в запрос не попало.

**Параметры модели (7B, 13B, 70B)** — примерное число обучаемых параметров
с приставками: B — миллиарды. Влияет на качество и на требуемую память,
но не является гарантией качества.

**Квантование** — уменьшение числа бит, в которых хранится каждый вес модели.
Снижает потребление памяти ценой небольшой потери точности.

**VRAM** — память видеокарты. Для инференса LLM это главный ограничитель:
модель целиком помещается в память видеокарты.

**Пропускная способность памяти (bandwidth)** — скорость, с которой GPU
читает веса модели. Определяет, сколько токенов в секунду выдаёт сервер.

**Инференс (inference)** — работа уже обученной модели: получение ответа
на запрос. В отличие от обучения, выполняется постоянно в проде.

**TCO** (Total Cost of Ownership) — полная стоимость владения: железо,
электричество, лицензии, сопровождение, обучение.

**Промпт** — текстовый запрос к модели вместе с инструкциями.

**Дообучение (fine-tuning)** — дополнительное обучение готовой модели на
своих данных, чтобы она лучше следовала вашему формату и домену.

## LLM-системы в продакшне

**LLMOps** — практики надёжной эксплуатации LLM-систем: версионирование,
тестирование качества, наблюдаемость, контроль издержек, безопасность.

**Галлюцинация** — правдоподобный по форме, но неверный по содержанию ответ
модели. Возникает потому, что модель генерирует наиболее вероятное
продолжение, а не проверяет факты.

**Groundedness / faithfulness** — насколько ответ опирается на предоставленный
контекст, а не на «знание» модели.

**LLM-as-a-judge** — оценка ответов другой моделью по заданным критериям,
вместо ручной проверки человеком.

**Регрессия качества** — ухудшение ответов после изменения промпта, модели,
данных или параметров. Ловится только автоматической проверкой на
золотом наборе.

**RAG** (Retrieval-Augmented Generation) — подход, при котором перед
генерацией модель получает релевантные фрагменты из базы знаний. Позволяет
отвечать на вопросы о корпоративных данных и снижает галлюцинации.

**Чанкинг (chunking)** — разбиение документов на части, которые попадают
в контекст по отдельности.

**Retrieval** — поиск релевантных фрагментов в векторной базе по запросу.

**Рерранкинг (reranking)** — второй проход сортировки найденного: более
точная модель переупорядочивает выдачу, поднимая действительно полезное.

**Промпт-инъекция (prompt injection)** — попытка заставить модель игнорировать
системные инструкции через пользовательский ввод или через данные в контексте.

**MCP** (Model Context Protocol) — открытый протокол, стандартизующий подключение
модели и агента к внешним системам (файлы, базы, внутренние API).

**Агент** — компонент, который вызывает модель в цикле: получает ответ,
принимает решение вызвать инструмент, выполняет действие, повторяет.

**Tool calling / function calling** — механизм, при котором модель возвращает
не текст, а запрос на вызов функции с аргументами.

**Трассировка LLM (tracing)** — запись пути запроса по LLM-пайплайну с промптами,
ответами, токенами и стоимостью каждого шага.
