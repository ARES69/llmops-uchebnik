Предыдущая лекция [про API-шлюз к LLM](mlops/11-api-shlyuz.md) дала тебе голый HTTP-клиент: один запрос — один ответ. Эта лекция — про то, что добавляется поверх, когда одного запроса перестаёт хватать: цикл принятия решений, вызов функций, память, фреймворки. И — главное — про дисциплину «сначала докажи, что агент вообще нужен». Умение объяснить, почему в твоей задаче хватит RAG с одним запросом, экономит месяцы разработки и нервы инфраструктуры.

## Сначала вопрос «нужен ли тут агент?»

Агент — это не «LLM, у которого есть инструменты». Технический агент — это цикл, в котором **следующий шаг выбирается по результату предыдущего**. Если маршрут решения известен заранее, агент не нужен: нужен обычный код.

| Задача | Нужен ли агент | Почему |
| --- | --- | --- |
| Ответить на вопрос по базе знаний | Нет | RAG: один запрос с найденным контекстом, дешевле и предсказуемее |
| Разложить письмо на поля (тема, дата, сумма) | Нет | Structured output по JSON-схеме, без цикла |
| Разобрать 500 писем по 8 категориям | Скорее нет | Батч-вызов + дешёвая модель; агент тут дороже в 5–10 раз |
| «Что с оплатой по договору №44?» | Зависит от данных | Один хаб-поиск — RAG; если нужно сходить в биллинг, найти договор, сверить суммы — агент |
| Собрать отчёт из CMDB + Jira + почты + БД | Да | Маршрут заранее неизвестен, число шагов зависит от находок |
| Разбор инцидента по логам | Да | Ветвление «нашёл исключение → полез за контекстом», «не нашёл → расширить поиск» |
| Выполнить 200 однотипных операций по списку | Нет | Скрипт: детерминированно, повторяемо, в 100 раз дешевле |
| Написать и починить код в репозитории | Да | Итерации, проверки, откат к предыдущему шагу |

> [!CAUTION]
> Термин «агент» в продуктовых презентациях означает «LLM с подключёнными
> инструментами». Если система делает один-два фиксированных вызова, это
> workflow, а не агент: называй так честно — от этого зависит бюджет,
> безопасность и ожидания пользователя.

Правило для архитектора: **агент оправдан там, где число шагов и их порядок зависят от данных**. Всё остальное — RAG плюс обычный код. Самый частый провал внедрения — собрать агента там, где хватило бы двух промптов, а потом полгода чинить его непредсказуемость и стоимость.

## Что внутри агентного цикла

Классическая схема ReAct (рассуждение → действие → наблюдение) сегодня реализуется не свободным текстом, а структурированным вызовом функции. Модель не пишет «я подумаю и вызову погоду», а возвращает структуру `tool_calls`. Цикл приложения упрощается до четырёх шагов:

1. Собрать системный промпт, историю диалога и список инструментов в виде JSON-схем.
2. Отправить это в `/chat/completions` с параметром `tools`.
3. Если в ответе есть `tool_calls` — выполнить их, положить результаты в историю ролью `tool`, повторить п. 2.
4. Если `tool_calls` нет — это финальный ответ, цикл завершён.

Планирование (plan-and-execute) добавляет перед циклом отдельный вызов, где модель составляет список шагов. Это полезно для длинных задач: план можно показать человеку, выполнение идти по нему, а не переписывать на каждой итерации. Плата — два вызова вместо одного и риск выполнить устаревший план.

## Инструменты: как модель вызывает функцию

Инструмент — это JSON-схема с именем, описанием и параметрами. Описание важнее, чем кажется: модель выбирает инструмент по тексту описания, а не по имени. Расплывчатое «получить данные» даст вызовы не туда; конкретное «текущая погода в городе, только для городов РФ» — в нужную сторону.

```python
# tools.py — объявление инструментов для любого OpenAI-совместимого API
TOOLS = [
    {
        "type": "function",
        "function": {
            "name": "get_weather",
            "description": "Текущая погода в городе. Возвращает температуру и осадки.",
            "parameters": {
                "type": "object",
                "properties": {
                    "city": {"type": "string", "description": "Название города на русском языке"},
                    "unit": {
                        "type": "string",
                        "enum": ["c", "f"],
                        "description": "Единицы измерения: c — Цельсий (по умолчанию), f — Фаренгейт",
                    },
                },
                "required": ["city"],
                "additionalProperties": False,
            },
        },
    },
    {
        "type": "function",
        "function": {
            "name": "get_cmdb",
            "description": "Карточка узла из CMDB: владелец, среда, стенд, тип ОС.",
            "parameters": {
                "type": "object",
                "properties": {"hostname": {"type": "string"}},
                "required": ["hostname"],
                "additionalProperties": False,
            },
        },
    },
]
```

Параметры вызова приходят строкой JSON в `tool_calls[].function.arguments` — их надо распарсить и **проверить по той же схеме**. Модель регулярно приносит мусор: несуществующее имя инструмента, `unit: "Celsius"` вместо `c`, лишний ключ, пустой обязательный аргумент, а иногда — рассуждение вперемешку с аргументами.

Полный цикл в одном месте: объявление, валидация, выполнение, возврат результата и защита от бесконечного шага.

```python
# agent_min.py — агент на голом OpenAI-совместимом клиенте
import json, os, sqlite3, time, uuid
from jsonschema import Draft202012Validator
from openai import OpenAI

BASE_URL = os.getenv("LLM_BASE_URL", "http://127.0.0.1:11434/v1")
MODEL = os.getenv("LLM_MODEL", "qwen2.5:14b-instruct")
DB_PATH = "kb.sqlite"

SYSTEM = (
    "Ты — помощник инженера эксплуатации. Бери факты только из инструментов. "
    "Если данных нет — прямо скажи, что не знаешь. Не выдумывай значения."
)

# ---------- инструменты ----------

def kb_bootstrap() -> None:
    """Создаёт демо-базу знаний, чтобы пример запускался без внешних сервисов."""
    if os.path.exists(DB_PATH):
        return
    con = sqlite3.connect(DB_PATH)
    con.execute("CREATE TABLE docs (id INTEGER PRIMARY KEY, title TEXT, body TEXT)")
    con.executemany(
        "INSERT INTO docs (title, body) VALUES (?, ?)",
        [
            ("Регламент перезагрузки ВМ", "Плановое обслуживание ВМ — вторник, 02:00–04:00 МСК, согласование за 3 дня."),
            ("Политика паролей AD", "Минимум 14 символов, срок 90 дней, запрет повтора последних 5 паролей."),
            ("Порядок эскалации", "Инциденты P1 дежурный инженер → руководитель эксплуатации в течение 15 минут."),
        ],
    )
    con.commit()
    con.close()


def search_kb(query: str, top: int = 3) -> list[dict]:
    """Поиск по внутренней базе знаний. Параметры запроса — только через плейсхолдеры."""
    con = sqlite3.connect(DB_PATH)
    try:
        rows = con.execute(
            "SELECT id, title, body FROM docs WHERE body LIKE ? OR title LIKE ? LIMIT ?",
            (f"%{query}%", f"%{query}%", top),
        ).fetchall()
    finally:
        con.close()
    return [{"id": r[0], "title": r[1], "excerpt": r[2][:240]} for r in rows]


def get_cmdb(hostname: str) -> dict:
    """Карточка узла. В бою здесь HTTP-запрос к твоему CMDB с таймаутом."""
    with open("cmdb.json", encoding="utf-8") as fh:
        cmdb = json.load(fh)
    card = cmdb.get(hostname.lower())
    if card is None:
        return {"error": f"узел {hostname} не найден в CMDB"}
    return card


def get_weather(city: str, unit: str = "c") -> dict:
    """Погода. Требует METEO_URL — внутреннего сервиса метеостанций."""
    import httpx
    url = os.environ.get("METEO_URL")
    if not url:
        return {"error": "сервис метеостанций не сконфигурирован"}
    try:
        r = httpx.get(url, params={"city": city}, timeout=3.0)
        r.raise_for_status()
        return {"city": city, "unit": unit, **r.json()}
    except Exception as exc:
        return {"error": f"сервис недоступен: {type(exc).__name__}"}


TOOLS_IMPL = {"search_kb": search_kb, "get_cmdb": get_cmdb, "get_weather": get_weather}
SCHEMAS = {t["function"]["name"]: t["function"]["parameters"] for t in TOOLS}

# ---------- цикл ----------

def run(user_text: str, max_steps: int = 6, token_budget: int = 40_000) -> dict:
    client = OpenAI(base_url=BASE_URL, api_key=os.getenv("LLM_API_KEY", "ollama"), timeout=30)
    run_id = uuid.uuid4().hex[:12]
    messages = [{"role": "system", "content": SYSTEM}, {"role": "user", "content": user_text}]
    spent, transcript = 0, []

    for step in range(max_steps):
        resp = client.chat.completions.create(
            model=MODEL, messages=messages, tools=TOOLS, temperature=0, parallel_tool_calls=False
        )
        spent += resp.usage.total_tokens
        msg = resp.choices[0].message

        if not msg.tool_calls:
            transcript.append({"step": step, "type": "final", "text": msg.content})
            return {"run_id": run_id, "answer": msg.content, "tokens": spent, "transcript": transcript}

        messages.append(msg.model_dump(exclude_none=True))
        for call in msg.tool_calls:
            name, raw = call.function.name, call.function.arguments
            try:
                args = json.loads(raw or "{}")
                Draft202012Validator(SCHEMAS[name]).validate(args)
                impl = TOOLS_IMPL.get(name)
                result = impl(**args) if impl else {"error": f"инструмент {name} не объявлен"}
            except Exception as exc:
                # Ошибку отдаём модели как результат инструмента, а не роняем прогон
                result = {"error": f"{type(exc).__name__}: {exc}"}
            body = json.dumps(result, ensure_ascii=False)
            transcript.append({"step": step, "type": "tool", "tool": name, "args": args, "result": result})
            messages.append({"role": "tool", "tool_call_id": call.id, "content": body})

        if spent > token_budget:
            return {"run_id": run_id, "answer": "Бюджет токенов исчерпан, ответ неполный.",
                    "tokens": spent, "transcript": transcript}

    return {"run_id": run_id, "answer": "Достигнут лимит шагов, задача не завершена.",
            "tokens": spent, "transcript": transcript}


if __name__ == "__main__":
    kb_bootstrap()
    print(json.dumps(run("Под какой пароль у нас AD и что делать при инциденте P1?"),
                     ensure_ascii=False, indent=2))
```

```bash

export LLM_MODEL=qwen2.5:14b-instruct
echo '{"app01.corp": {"owner": "infra", "env": "prod", "os": "Ubuntu 24.04"}}' > cmdb.json
python agent_min.py
```

Что здесь важно конструктивно:

- **Ошибка аргументов — это результат, а не исключение.** Модель видит `{"error": "ValidationError: ..."}`, исправляет вызов и идёт дальше. Если поднимать исключение наружу, ты теряешь прогон из-за опечатки модели.
- **`parallel_tool_calls=False`** — сознательное решение: параллельные вызовы экономят один раунд, но ломают порядок и усложняют отладку. Включай, когда инструменты независимы и идемпотентны.
- **Три ограничителя вместо одного**: число шагов, токен-бюджет, таймаут клиента. Любой агент без них — это генератор инцидентов по счёту.

## Что делать, когда модель галлюцинирует вызов

Типовые сбои и реакция:

| Сбой | Симптом | Реакция |
| --- | --- | --- |
| Несуществующее имя инструмента | `KeyError` в словаре диспетчера | Проверка по белому списку, вернуть модели текст «такого инструмента нет, доступны: ...» |
| Аргументы не по схеме | `ValidationError` | Валидация по JSON-схеме, возврат ошибки в цикл |
| Несуществующий `tool_call_id` | 400 от API | Всегда возвращай ровно тот `id`, который пришёл |
| Цикл вызовов | Один и тот же инструмент 10 раз | Счётчик на инструмент + лимит повторов подряд |
| Результат инструмента трактуется как приказ | Агент выполняет «инструкцию» из данных | Разделительные маркеры и запрет на исполнение директив из результата — это [лекция 14](mlops/14-bezopasnost-agentov.md) |
| Модель пишет рассуждение в поле ответа | Невалидный JSON | Обрезка до первой `{`, повторный вызов с подсказкой |

Опция `tool_choice` управляет этим на уровне API: `auto` (по умолчанию), `none` (запретить вызовы — режим финального ответа), `required` (обязательно вызвать инструмент), `{"type":"function","function":{"name":"..."}}` (вызвать конкретный). Принудительный вызов удобен для детерминированных шагов пайплайна.

## Фреймворки: что они добавляют

Фреймворк берёт на себя три вещи: сборку контекста, цикл и состояние, интеграции с внешними системами. Чем больше у тебя второго — тем честнее он окупается.

| Фреймворк | Что решает | Цена сложности | Зрелость | Зависимости | Когда брать |
| --- | --- | :---: | :---: | :---: | --- |
| LangChain + LangGraph | Цикл, состояние, чекпойнты, параллельные ветки, HITL | Высокая | Высокая | Много (~200) | Продакшн с ветвлением, паузами и восстановлением |
| LlamaIndex | Данные: загрузчики, индексы, RAG, Workflows | Средняя | Высокая | Средне | Много разных источников, сложный RAG |
| CrewAI | Роли, цели, «экипажи» агентов | Низкая | Средняя | Мало | Быстрый прототип, много параллельных ролей |
| OpenAI Agents SDK | Handoffs, guardrails, трейсинг, сессии | Низкая | Растёт | Мало | Если уже в экосистеме OpenAI, нужен трейсинг из коробки |
| smolagents | Агент, пишущий Python вместо JSON-вызовов | Очень низкая | Растёт | Мало | Эксперименты, локальные модели, быстрые хаки |
| Low-code (Dify, Langflow, Flowise, n8n) | Визуальная сборка, интеграции без кода | Низкая для разработки, высокая для эксплуатации | Средняя | — | Прототип, непрофильные процессы, стыковка с ITSM |

> [!WARNING]
> LangChain 1.0 (октябрь 2025) — это уже не «цепочки промптов», а
> `langchain.agents.create_agent` поверх рантайма LangGraph. Старые
> tutorials по `LLMChain`, `AgentExecutor` и `initialize_agent` не работают
> на актуальных версиях. Плати и за это тоже: у пакета тяжёлое дерево
> зависимостей, и он сам становится вектором supply chain.

```bash
# сравнение веса зависимостей — полезно знать до того, как тащить в прод
pip install openai jsonschema httpx pydantic     # единицы пакетов
pip install langchain langgraph                  # сотни пакетов
pip install --dry-run langchain langgraph | tail -3   # сколько именно будет поставлено
```

Честная позиция: **для двух-пяти инструментов фреймворк — лишний слой**. Цикл из примера выше — это 80 строк. Он читается целиком, его можно отладить, у него нет транзитивных обновлений, ломающих прод в пятницу вечером. Фреймворк становится выгоден, когда выполняются хотя бы три условия: больше одного места ветвления, нужна остановка и продолжение с возобновлением (чекпойнты), нужны параллельные ветки или человек в контуре, команда больше одного разработчика и все должны говорить на одном языке. Одно из условий — спорно, три — повод мигрировать.

## Память и состояние

Термин «память агента» скрывает четыре разных сущности, и путать их дорого.

| Вид | Где лежит | Срок | Главный риск |
| --- | --- | :---: | --- |
| Краткосрочная | История диалога в контексте модели | Диалог | Рост стоимости и задержки, вытеснение системного промпта |
| Рабочая | Переменные текущего прогона (шаги, накопленные данные) | Один запуск | Потеря при рестарте процесса |
| Долговременная (факты) | SQL: «пользователь X работает в ЦОД, окно обслуживания — вт» | Месяцы–годы | **Залипание** на неверном факте |
| Семантическая | Векторная БД: прошлые диалоги, документы | Годы | Приватность, смешанные источники, «галлюцинация памяти» |

Правила, которые экономят нерги:

- Каждый факт хранится **с источником, датой и уровнем уверенности**. Факт без источника — это гадание, записанное в базу навсегда.
- У фактов есть TTL. Согласование окна обслуживания полгода назад не значит, что оно действует сейчас.
- Есть явная операция «забыть» и команда пользователя «это больше неверно, забудь». Без неё ошибка живёт вечно и заражает все последующие ответы.
- Факт из документа хранится вместе с цитатой, иначе непроверяемо.
- Никаких персональных данных в памяти без маскирования — память читается при каждом запросе и попадает в трейсы.

## Управление потоком: состояние, ветвление, повторы

Когда шагов больше трёх и у них есть развилки, цикл `while` перестаёт читаться. Модель состояний (граф) делает маршрут явным: узлы — шаги, рёбра — переходы, состояние — данные прогона, чекпойнты — возможность остановиться и продолжить с середины.

```python
# graph.py — тот же агент, но с явным состоянием и чекпойнтами (LangGraph)
from typing import Annotated, Literal, TypedDict
from langgraph.graph import StateGraph, START, END
from langgraph.checkpoint.sqlite import SqliteSaver

class State(TypedDict):
    messages: list
    steps: int
    answer: str | None

MAX_STEPS = 6

async def agent_node(state: State) -> State:
    resp = await llm.ainvoke(state["messages"])
    state["messages"].append(resp)
    return {"steps": state["steps"] + 1}

async def route(state: State) -> Literal["tools", "__end__"]:
    last = state["messages"][-1]
    if getattr(last, "tool_calls", None):
        return "tools"
    return "__end__"

async def tools_node(state: State) -> State:
    from langgraph.prebuilt import ToolNode
    return await ToolNode(TOOLS_IMPL).ainvoke(state)

g = StateGraph(State)
g.add_node("agent", agent_node)
g.add_node("tools", tools_node)
g.add_edge(START, "agent")
g.add_conditional_edges("agent", route, {"tools": "tools", "__end__": END})
g.add_edge("tools", "agent")

checkpointer = SqliteSaver.from_conn_string("agent_state.db")
app = g.compile(checkpointer=checkpointer)
# recursion_limit — страховка от бесконечного цикла на уровне рантайма
config = {"configurable": {"thread_id": session_id}, "recursion_limit": MAX_STEPS * 2}
```

Зачем тебе это как DevOps-инженеру: чекпойнт в `agent_state.db` означает, что упавший на пятом шаге прогон можно продолжить, а не начинать заново и платить двойную стоимость. И это же даёт место для ручного подтверждения посередине — то, о чём пойдёт речь в [следующей лекции](mlops/14-bezopasnost-agentov.md).

## Наблюдаемость с первого дня

Агент без логов — чёрный ящик, который стоит денег на каждый вызов. Пиши JSONL на каждом шаге, а не один итоговый лог «запрос-ответ».

```python
# observability.py — минимальный набор полей, который потом уедет в Loki/ClickHouse
import json, logging, time, uuid

log = logging.getLogger("agent")
log.setLevel(logging.INFO)

def log_step(run_id: str, step: int, event: str, **fields) -> None:
    record = {
        "ts": round(time.time(), 3),
        "run_id": run_id,
        "step": step,
        "event": event,          # llm_call | tool_call | tool_error | final | budget_stop
        "prompt_version": "2026-03-01.2",   # хэш/версия промпта — обязательно
        "model": MODEL,
        **fields,
    }
    log.info(json.dumps(record, ensure_ascii=False))
```

Что должно попадать в лог всегда: `run_id` (сквозной идентификатор), номер шага, имя инструмента, аргументы **после санитизации**, признак успеха, задержка, токены вход/выход, модель, версия промпта. Чего в обычный лог не кладут: полный текст промпта и содержимое результатов инструментов, если там могут быть персональные данные — их уводят в отдельное защищённое хранилище с доступом по ролям. Как это собрать в метрики и дашборды — [лекция про наблюдаемость LLM](mlops/16-nablyudaemost-llm.md).

> [!TIP]
> Минимальный набор метрик, ради которых всё это затевается: доля прогонов,
> дошедших до финального ответа; среднее число шагов; доля прогонов,
> упёршихся в лимит шагов; стоимость на один успешный результат; p95 задержки.

## Детерминизм и воспроизводимость

`temperature=0` не даёт детерминизма. Батчинг, квантизация и версии ядер CUDA дают расхождения между прогонами на одном и том же запросе. Для воспроизводимого разбора инцидента этого мало:

- Фиксируй **снапшот модели**, а не алиас: `gpt-4o-2024-08-06`, а не `gpt-4o`. Для локальных моделей — digest, а не тег.
- Промпты живут в Git, в лог пишется их версия или хэш.
- Полная трасса (запрос, ответ, аргументы, результаты, тайминги) сохраняется для офлайн-разбора.
- Поддерживается `seed`, если бэкенд его уважает.
- Под промпт и модель есть golden-набор из 50–100 кейсов с ожидаемыми свойствами ответа, который гоняется в CI до выката.

```bash
# digest локальной модели — его и пишем в лог рядом с run_id
curl -s http://127.0.0.1:11434/api/tags | jq -r '.models[] | "\(.name)\t\(.digest)"'
curl -s http://127.0.0.1:11434/api/ps | jq -r '.models[] | "\(.name)\tuntil: \(.expires_at)"'
```

> [!CAUTION]
> Замена модели на соседнюю версию того же семейства меняет поведение агента
> сильнее, чем любой рефакторинг промпта. Снапшот модели — часть контракта,
> и его смена идёт через тот же CI, что и смена промпта.

## Интеграция без кода: n8n

Если стек отдела уже построен вокруг n8n, агентный шаг в нём собирается без разработчика Python: ноды AI Agent, Chat Model, Tool-ноды и **MCP Client Tool** — последний подключает любой MCP-сервер напрямую. Плюсы — быстрый пилот, интеграция с существующими триггерами, логи в интерфейсе. Минусы — оркестратор становится частью прода, изменения в нём не проходят твой CI, а права ноды «HTTP Request» в твоей сети легко перестают быть минимальными. Правило: n8n — для пилотов и для процессов без доступа к критичным системам; агент с правами на AD, почту или БД пиши кодом, где права выдаются декларативно и ревьюятся.

## Где это ломается

- **Агент там, где хватило RAG.** Платишь в 5–10 раз больше за токены, получаешь недетерминированный ответ и новый класс инцидентов. Начинай всегда с одного запроса.
- **Без лимита шагов.** Модель зацикливается на «поищу ещё раз», двадцать вызовов подряд, счёт на конец месяца. Лимиты — в коде, не в промпте: «не используй больше 5 шагов» модель нарушит при первом же сбое инструмента.
- **Ошибка инструмента роняет прогон.** Исключение из HTTP-клиента улетает наружу, пользователь видит 500, агент мог бы переспросить модель. Ошибку надо возвращать как результат.
- **`msg.content or ""` забыт при возврате assistant-сообщения.** Модель отвечает одновременно текстом и `tool_calls`; выбросив текст, ты ломаешь рассуждение и получаешь скачки качества после обновления модели.
- **Аргументы без валидации.** `LIKE "%" + query + "%"` из строки модели — это и SQL-инъекция, и лишний полный скан таблицы. Только плейсхолдеры плюс схема.
- **Фреймворк, выбранный «потому что все выбирают».** 200 зависимостей, три недели на апгрейд, дебаг через четыре слоя абстракции. Для двух инструментов — лишний слой.
- **Память как свалка.** Неверный факт, записанный один раз, живёт год и тихо портит все ответы. Нет TTL и нет команды «забудь» — это не память, а долг.
- **Логи без `run_id`.** Разбирать инцидент по вплетённым в текст логам невозможно; связка «ответ пользователя → шаги» теряется сразу.
